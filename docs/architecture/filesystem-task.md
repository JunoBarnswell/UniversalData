# File System Task

`file.system` is a native Task descriptor, not a file execution engine. It supports `operation: copy | move | delete | mkdir` with logical `source`/`target` connection ids. Copy/move require both ids, delete only source, mkdir only target. Unknown options/operations/connections are rejected by the existing Task configure hook before external I/O. Task configure is optional pure validation using the same component callback ABI with NULL schema arrays.

The existing Connection Manager resolves Package/Project bindings and authorization. File-only acquisition rejects other driver kinds before library/credential loading. All leases require host OPEN authorization; copy requires source READ and target WRITE, move also requires source DELETE, delete requires DELETE, mkdir requires target WRITE. `UD_ACCESS_DELETE=8` is distinct from row write modes and reserves existing quarantine actions 6/7. Missing authorization is denial. The staging file's WRITE authorization is also explicit and copy rechecks source/target grants during each chunk.

Operations are intentionally bounded: regular files only; no recursive deletion, directory copy, overwrite or implicit cross-device copy fallback. Paths must be absolute, without `.`/`..` segments; filesystem inspection rejects symlinks/reparse points and special files in the path. The host owns directory trust and OS permissions; this is not an adversarial filesystem namespace sandbox.

Copy reads a regular file into a quota-charged 64 KiB buffer, writes an exclusively created `.ud-task.part`, flushes, checks cancellation/authorization, then atomically publishes the new target name without replacing an existing file. It removes only staging it created. Existing targets and staging files are preserved. Copy does not promise a snapshot of a source modified concurrently by an external writer. Move uses Linux `renameat2(RENAME_NOREPLACE)` (or the platform's no-replace move), then synchronizes directory entries. Unsupported no-replace primitives and cross-device moves fail without a copy fallback. Delete only removes regular files; absent files are idempotent. mkdir creates one directory level and accepts an existing directory.

The shared Execution cancellation/deadline checks bound the copy loop; sources use a nonblocking/no-follow regular-file open to avoid a substituted FIFO blocking launch. Failure/cancellation before publication removes owned staging. An unconfirmed publication/directory-sync result is CommitUnknown. Task-level checkpoint completion skips an already completed operation on resume; an interrupted File System invoke is **not** declared replay-safe and requires outcome verification rather than repeating a possible move/delete/copy effect. This shares the existing Journal and state model.

`tests/filesystem_task.c`/`.py` verify Unicode/binary copy, no-overwrite move, delete/mkdir, deletion grants, default deny, cancellation before and during copy, grant revocation, source/target/staging preservation, config/path/symlink/FIFO rejection, completed resume and real process termination after external effect before task acknowledgement. The C/.NET/Java parity Package now executes the same file copy and child pipeline (completed tasks 7). Evidence: `docs/acceptance/evidence/ssis-filesystem`.
