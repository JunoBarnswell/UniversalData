# Execute Process Task

`process.execute` is a native Task on the existing Execution, registry, scope, deadline and Journal services. A logical connection with `driver: process` names an absolute executable resource. No driver library or credential resolver is loaded for that endpoint. The same Connection Manager performs host OPEN and explicit `UD_ACCESS_EXECUTE=9` authorization; absent callback or denied EXECUTE prevents launch. The CLI's file-root policy always denies EXECUTE. Hosts can grant it through the SDK's existing authorizer after checking a trusted program.

Configuration contains `connection`, optional string-array `arguments`, optional file-connection `workingDirectory`, `timeoutMs` (default 60 seconds, max 24 hours), `expectedExitCode` (default 0) and writable int64 `exitCodeVariable`. Pure Task configure rejects unknown members, malformed/NUL arguments, more than 1024 arguments/1 MiB total text, unknown connections and read-only or incorrectly typed output variables before launch. Programs receive an argv array directly; the task does not add a shell. Empty/Unicode/quoted arguments retain their identity. Explicitly authorizing a shell still authorizes that trusted program, not a sandbox.

Child stdin/stdout/stderr use the null device; their text never enters SDK diagnostics, events or implicit history. Environment defaults are inherited. The host owns program trust, credentials, OS permissions and child memory/CPU restrictions. The Execution quota charges SDK argument/command builders, not all memory of an external OS process. This task does not promise containment of a program that deliberately detaches or alters its process group.

On Linux, the supervisor launches a session/process group, closes inherited descriptors and uses a close-on-exec failure pipe to distinguish a failed exec from a program returning 127. It observes termination without first reaping the leader, kills remaining group members, and then reaps it; the reserved PID avoids signaling a reused group id. Hosts must retain ownership of these child PIDs instead of reaping them in an unrelated SIGCHLD handler. Local timeout returns Transient; the shared Package deadline/cancel returns Cancelled. Cleanup reaps the direct child and terminates ordinary descendants; external effects are not rolled back. The guarded Windows path uses explicit handle inheritance, quoted UTF-16 arguments and a Job Object; per user instruction it is not tested or claimed verified.

Expected exit status is configurable; unexpected exit or exec failure returns IO. The optional int64 output receives an observed status, with negative signal status on Linux; a denied/unstarted launch does not change it. Process invocations are not replay-safe. Completed Task checkpoints skip them, while interrupted invocation returns CommitUnknown/RecoveryRequired and requires outcome verification. No new executor or global exactly-once claim is introduced.

`tests/process_task.c`/`.py` verify actual argument/cwd delivery, default/explicit execution denial, exit policy versus exec failure, real local/Package timeout and live cancellation with child/descendant cleanup, validation errors, and real effect-before-checkpoint process termination followed by Unknown recovery. Linux native and ASan evidence is saved under `docs/acceptance/evidence/ssis-process`; the existing three-language file/child/data parity suite is rerun as a regression check, not represented as a positive process-authorization test in managed consumers.
