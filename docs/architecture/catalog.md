# Native indexed Catalog

The Package component owns one SQLite Catalog implementation. The Catalog stores immutable documents and indexed product metadata; it never executes a Package or supplies a transaction recovery decision. Native Journal remains the owner of execution recovery facts. Each host owns a context and serializes calls on each Catalog handle; independently opened handles and Worker processes share SQLite transactions and WAL.

The database is `catalog.sqlite3` in the explicitly authorized Catalog directory. `application_id` identifies UniversalData and `user_version` encodes protocol 10 and storage revision 2 (`655362`). Native upgrades the former protocol-10 SQLite document layout under a writer transaction, preserving every document and digest; older binaries reject the revised storage version. Another application or protocol is rejected. No `.udc` query path exists. Old `.udc` artifacts are preserved and ignored. Creating or opening the database requires the configured host policy; every public read or write rechecks the corresponding grant.

The document primary key is `(tenant, kind, id, revision)`. Revisions retain the complete positive uint64 domain as fixed-width decimal keys, so indexed lexical ordering matches revision ordering. Documents cannot be overwritten: the same key and canonical document is idempotent; a different document returns `CORRUPT`. Package, Project, Environment and Deployment validation uses the existing Native model and exact immutable references. No service-side package validator or alternate binding path is introduced.

Each stored row has a SHA-256 digest over protocol, tenant, kind, id, revision, explicit timestamp and canonical document. Reads and query pages verify the physical key and digest. This detects corruption and accidental key changes; the host remains responsible for control of its authorized directory. Writes use an immediate SQLite transaction, and an interrupted writer cannot publish uncommitted documents. WAL and FULL synchronization provide the storage durability boundary.

`ud_catalog_get` and `ud_catalog_list` use indexes for the current tenant and kind. `ud_catalog_query` accepts a strict Native query document with kind, optional exact id, `(afterId, afterRevision)` cursor, explicit timestamp bounds and a limit of 1–1000. Results include immutable id, revision and document. There is no directory enumeration, per-file checksum scan, unbounded page or host-maintained duplicate index. Timestamp queries use values explicitly stored in documents, not inferred execution facts.

Events retain execution/task/pipeline/component identity, state, result, time and sequence. Ready/terminal execution snapshots retain Native metrics and fingerprints without raw parameter or credential values. Arbitrary supplied documents remain subject to the host's data policy. Durable job scheduling, log retention and Web process management are separate incomplete 2.0 items; their status remains in `metadata/product.json`.

`tests/catalog.c`, `tests/catalog.py` and `tests/catalog_history.py` cover immutable versions, page cursors, tenant isolation and revocation, protocol refusal, digest/key corruption, independent native writers, a held SQLite writer, process termination before commit, reopen and preservation of old artifacts. These tests are registered for the concentrated ABI 10 gate and have not yet been executed on this branch. Historical ABI 9 results do not certify this implementation.

Conditional document updates and dispatch ownership share these same SQLite transactions. `ud_catalog_compare_exchange` appends only revision `expected+1`; protected objects also require a matching live lease. Lease generations are durable, monotonically increasing fencing tokens, including after release or process death. Pool capacities are fixed at first use and mismatching node policies are rejected. Lease expiry only removes authority; it cannot prove the absence of external effects. The persisted server clock is monotone across accepted/rejected fencing decisions. Hosts also use a local watchdog and terminate a Worker when renewal fails.

Management instances query current heads with `latestOnly`, acquire Native run/job leases, renew active execution authority and append fenced state transitions. The old global management lock is removed. A different manager reconciles an expired Claimed/Running record into RecoveryRequired and preserves its Native execution ID. Pending ordinary REST writes remain unknown on manual recovery; Catalog status cannot override Native Journal facts. Cancellation requests are persistent and bound to an attempt.

Multiple manager processes currently share one **server-local** SQLite Catalog and host resource layout. This is not a remote Worker agent implementation or a supported SQLite-on-network-filesystem deployment. Cross-machine Worker transport, Cron/calendars and the wider enterprise scheduler remain Partial in the existing product model. Newly registered Native lease/process-kill and two-manager acceptance tests require execution before certification.

Private Worker wire revision 2 transports canonical Native Catalog records for both live events and bounded recovery pages. The Worker persists each Native event before sending it, continues event sequence and execution revisions from the maximum durable Native facts, and imports records missed by management before the next start handshake. Legacy requests are rejected. A preflight failure while resolving an unknown execution cannot erase RecoveryRequired. Current Linux acceptance passed 72 core tests, including a two-manager kill/manual-resume case that checks the actual resumed Native terminal snapshot and one external POST effect.
