# HTTP Task

`http.request` is a registry Task on the existing Execution, lexical scope, cancellation, deadline and Journal services. `UD_WITH_HTTP=ON` links optional libcurl >=7.85 into Package and the shared facade; the installed CMake package exports the same dependency. The default OFF build keeps the descriptor but returns Unsupported during pure configuration validation before I/O. Runtime libcurl must support TLS and asynchronous DNS. libcurl initializes once per implementation image and remains available for the process lifetime; one Execution never tears it down underneath another.

A Connection Manager definition `{ "id": "endpoint", "driver": "http", "resource": "https://host/path" }` owns the exact URL. Expressions and Project connection ownership follow the common binding rules. The built-in endpoint does not load a connector library. The host must grant OPEN and `UD_ACCESS_NETWORK=10`; there is no implicit grant when callbacks are absent. The URL permits HTTP/HTTPS, rejects embedded user/password, fragments and control characters. The host owns endpoint, tenant and routing policy. Environment proxies and netrc lookup are disabled. Redirects are never followed, including redirects to another authorized endpoint; this avoids forwarding a credential without a new host decision. The CLI's file-root policy always denies NETWORK.

Optional `credentialReference` uses the existing host resolver, scoped to tenant, exact resource and reference. It returns host-allocated JSON `{ "headers": { "Authorization": "Bearer ..." } }`, capped at 32 KiB and 64 headers. Header names/values are validated; routing/framing headers (Host, Content-Length, Transfer-Encoding, Connection, Expect, Proxy-Authorization, Content-Type) cannot be overridden by the resolver. Exceptions in Java/.NET callbacks deny access. The SDK does not emit credentials, URLs, request/response bodies or headers to diagnostics/events/history. The examples use an artificial fixture token, not a saved environment credential.

Configuration requires `connection`. Optional members are:

- `method`: GET (default), HEAD, POST, PUT, PATCH or DELETE. POST/PUT/PATCH accept a UTF-8 JSON string `body` up to 1 MiB, including embedded NUL, and optional `contentType` without control characters. GET/HEAD/DELETE do not accept a body.
- `timeoutMs`: default 60 seconds, range 1–86400000, shared across all attempts and backoff. The Package deadline and cancellation remain authoritative.
- `maxResponseBytes`: default 1 MiB, range 1–64 MiB. Bodies are streamed into a bounded byte counter and discarded; this Task does not implement an HTTP row Source/Destination. Response headers have a separate 64 KiB limit.
- `expectedStatus`: optional exact 100–599 status; otherwise only 2xx succeeds. `statusVariable` names a writable int64 variable receiving an observed HTTP status, including an HTTP error, unless the shared context has been cancelled.
- `maxAttempts`: default 1, at most 3, allowed above 1 only for GET/HEAD. Only HTTP 408/429/500/502/503/504 retry, using `retryDelayMs` (default 100 ms, max 60 seconds). Transport/TLS failures never retry. POST/PUT/PATCH/DELETE always have a single application attempt; invalid retry configuration fails before I/O. Retry-After and automatic redirect policies are not implemented.
- `caConnection`: optional logical file connection for an explicit CA bundle. OPEN/READ are authorized, symlinks/nonregular files are rejected, and at most 1 MiB is loaded through the shared quota into an immutable per-invocation blob. Otherwise the transport's system trust store applies. Peer and hostname verification are always enabled; there is no bypass setting.

Configuration validation rejects unknown members, unsupported methods, invalid numbers/body, malformed output bindings, and statically incompatible logical drivers before external I/O. Native libcurl multi polling checks host NETWORK grants and root cancellation/deadline at least every 50 ms during an ordinary transfer and during retry delay; body/header/progress callbacks also check them. Local timeout returns Transient, Package deadline/cancellation returns Cancelled, revoked authorization returns Auth, response limits return Resource, and transport/TLS/unexpected HTTP statuses return IO. Cleanup removes the handle from its multi controller, frees headers/trust/builders and releases the common lease. SDK builders and CA/body JSON are quota charged; libcurl/TLS internal buffers are bounded by their provider and are not charged as SDK allocations.

HTTP invocations are conservatively not replay-safe, including GET/HEAD: a server may have side effects. Completed Task checkpoints skip the request. A process killed after a request effect but before TaskDone resumes as CommitUnknown/RecoveryRequired without another request. External request effects cannot be rolled back, and this Task makes no end-to-end exactly-once claim.

Linux evidence under `docs/acceptance/evidence/ssis-http` covers real HTTP/HTTPS methods and body, status/error policy, scoped credentials/default deny, trusted TLS and rejected CA/hostname, no redirect forwarding, bounded retry/exhaustion and POST single attempt, limits, actual timeout/cancel/revocation, quota/schema rejection, effect-before-checkpoint termination and completed resume. Installed static/shared C consumers and NuGet/.NET/Maven/Java consumers use the same native implementation. Windows tests and remote CI status are waived by user instruction; HTTP Data Flow integration G61 remains a separate goal.
