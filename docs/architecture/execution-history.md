# Optional Catalog execution history

`ud_catalog_record_execution` records a caller-selected immutable revision of a Ready or terminal root Execution. It reads the existing native metrics and immutable identities; it never owns or drives the execution lifecycle. Hosts serialize this operation with start/destroy and decide how a Catalog error affects their logging policy. Running/Draining snapshots return `BUSY`, avoiding records from a partially swapped child definition frame.

The execution tenant must match the Catalog tenant. Records contain execution/package/project identifiers, exact Deployment metadata when present, definition/parameter fingerprints, state/result and the existing row, batch, queue, task, memory and spill metrics. Parameter values, component configuration, SQL, rows and resolved credentials are not copied into these records. Definition metadata and parameter fingerprints are prepared by the native Execution before execution begins, so cancellation does not require temporarily clearing its cancellation token or reserializing its parameters.

Use `ud_catalog_record_event` from the existing observer to append structured events with explicit monotonically increasing caller sequences. Ready/terminal snapshots and events remain separate Catalog kinds and immutable revisions; repeated identical snapshots are idempotent. Catalog is still an optional SDK repository, with no background logger or second execution core. The caller closes the Execution and Catalog through their existing lifetimes.

`tests/catalog_history.c`/`.py` run actual native success, failure, cancellation and CommitUnknown outcomes and check recorded metrics/status, tenant rejection, Running BUSY, repeated snapshots and repository reopening. They verify the stored parameter SHA-256 and Deployment revisions, validate envelope hashes, and scan persisted records for the supplied sensitive marker. Native callbacks' outcomes use a deterministic local test component; actual external-commit ambiguity/crash proof remains in the existing recovery suite.

This module provides explicit persistence of native run snapshots and events. Complete Audit/Parameter Set domain models, retry/wait/peak metric extensions, tracing/lineage, richer query/index/retention and automatic host integration remain separate work. No broader G47/G48 completion is claimed from this subset.
