# 数据库只读对账

本指南适用于当前问题对应的项目。实际数据源、业务入口、权限和表结构以该项目已确认的资料为准。

## 确认查询对象和实际数据源

- 从用户或工单提取目标环境、企业及客户编号、账套名、原始月份和凭证号、科目、存货或项目等业务键。尽量复用原报表的版本、模板、筛选项和显示口径。另选月份验证边界条件时，记录实际账期。
- 从正在使用的服务入口回溯配置。先确认部署环境和配置加载顺序，再找连接配置键、库名和分库路由。区分本地配置、环境配置和运行时配置中心。Navicat 名称用于定位登记，默认库为空或多个登记共用端点时，到服务配置和实际记录核实。端点一致只说明连接位置。核对该环境的库、账号权限及实际的目标账套。
- 数据字典和 ORM 实体可用来拟写 SQL。生产与文档字段不一致时，用目录视图确认指定库、表、列或索引，再改写查询。生产读请求以账套、期间、业务键为条件，只投影需要的列，并控制返回行数和查询超时。跨库对账时，分别按真实连接执行，每次执行一条已校验的 SELECT，再在本地按已确认的键比较结果。

## Finance 账套定位和物理表确认示例

仅在确认当前问题涉及 Finance 的相应账套架构时采用以下链路。其他系统沿各自的业务关系、租户键和实际分库规则定位。

1. **定位原账套。** `account_manage.account_relation_summary` 可按企业编号与客户编号、客户名或账套名查候选。结果为空时，继续找实际客户关系。在高级版代账关系库 `CRSDB`，用 `dbo.T_Company.CNumber` 找 `CCompanyID`，按企业关联 `dbo.T_Customer`，再通过客户 ID 关联 `dbo.V_TD_ZC_User_ZT.UserID`，同时限制同企业。结合客户编号、账套名、起始期间和当前期间缩小范围。视图记录缺失或过旧时，再用有据可依的账套关系实体或 `commonset` 中同企业的账套设置核对候选，最后用原期业务记录确认，例如同一天的凭证号。仅同名的多条候选应暂记为待确认。
2. **读取分库分表键。** 按已确认的 `ZTID` 查该环境身份库的 `commonset`（例如 `ydzidentity.commonset` 或 `unifyidentity.commonset`，以实际配置为准），核对账期与会计制度。仅从 `Setting` 提取用到的 `DBKey`、`BalanceKey`、`VoucherKey`、`VoucherEntryKey` 和业务相关开关。若在客户端解析 JSON，只在进程内读取原值，输出所选字段。
3. **验证实际物理库表。** 依据财务服务的 `SqlSugarFinancialChinaDbContext` 及其运行配置，将 `DBKey` 映射到连接配置键，并按 `DBHelper.ReplaceSplitTable` 确定余额、凭证和分录后缀。连接配置键编号、另一个服务的连接数组编号和物理库名后缀分别核对。在已授权的候选库先按 `ZTID` 和期间查主数据或账务表的存在性，得到相关记录后才确认路由。表存在但目标键为空时复查身份、分库、字段和期间。

## 按业务规则复算

- **库存跨月结存。** 用存货辅助项和分类关系定位存货 ID、入库科目与出库科目。比较同一存货及科目的上期 `EndQty`、下期 `BeginQty`，分别核对余额表、凭证分录数量及明细页公式。出库科目与库存科目不同时，按两种口径分别复算以定位明细差异。
- **科目余额借贷。** 对照一级非辅助余额、凭证头和凭证分录三组借贷合计。按现网表结构用凭证 ID 关联分录和凭证头，再按凭证头期间过滤，适配分录表缺少账期列的情形。检查单张凭证借贷、头与分录差额及缺分录，避免差额在月合计里相互抵消。
- **凭证功能条件。** 按日期、期间、凭证号确定当前记录，读取审核状态、来源及相关设置，按代码的校验顺序验证。查不到当前记录时按已确认的业务键检查删除表或合并关系。当前配置和历史操作分别记录。
- **应收应付与重分类。** 用报表项目、公式和科目关系查 `NumberRule`、加减符号及层级。分别计算主科目净额、末级或辅助明细的借方与贷方金额，逐公式核对转列和上下级重复取数。原月没有触发条件时，可选同账套有对应余额方向的月份复算，同时保留原月的核对结论。
- **期初试算。** 按会计制度和代码的试算口径核对 `initialbalance` 与后续期间余额。分别计算建账期初、累计发生额和相邻月衔接差额。仅有现存快照时，记录最早可见账期，变更时间以历史记录为依据。
- **项目利润表。** 定位项目辅助项，用当前模板和科目公式分别计算本期及累计金额。比较单选金额和同一项目在全选范围内的金额。全选请求中的标志、空列表及缺省值按真实入口检查。数据库复算和历史页面表现分别记录证据。

## 故障诊断与解决方案交付

- 按问题编号或名称写清用户现象、当期或历史范围、实际证据和复算差额。说明根因是否已确认、当前是否复现，以及需要补齐的日志、备份或请求记录。区分已观测数据与待验证假设。
- 对每条问题编号列出至少三种实质不同的方案。每项写明适用条件、实施动作、受影响的账套或功能、风险及回退方式、可检查的验收标准。按真实业务选择处理路径，例如复用现有入口、定向修复配置或数据、修正服务取数或展示。相同修复的拆分步骤或同一查询的语法改写合计为一个方案。
- 当前未复现或缺少历史证据时，先给出能立即采用的处理，例如依据当前数据完成对账或使用已验证的业务路径。备选方案各自写清获得何种证据后才能启动，以及该证据能证实哪一层的偏差。以有文档或代码依据的条件方案补足选择，避免将未知原因当作事实。
- 在每条问题的方案后标明唯一首选及编号，说明当前证据、适用面和风险如何支持该选择。需要先补证时，首选明确给出最小验证动作和继续实施的条件。
- 涉及代码、配置或账务变更的方案只作为建议，先在隔离测试环境验收。生产查询仍须逐条校验并获得授权。修复由有权限的人员通过所属业务的正式入口另行实施。

## 执行和交付

- 实际连接须在用户授权的环境和数据范围内。执行插件返回的原样 SELECT。Python 驱动要关闭会额外发出 SQL 的初始化选项，凭据仅从已授权配置读取到进程内。校验结果、会话和数据库的只读权限分别核对。
- 记录数据库和物理表、租户或账套键、期间、业务键、查询时间、实际值、复算公式或结果及已校验 SQL。说明差异是否复现、当前数据是否已变化、历史口径是否可查。连接失败、权限不足、表结构不符和无匹配记录是不同的结果，保留错误阶段或数据库错误码。
- 报告只保留对账所需字段。避免在 SQL 示例、输出、日志或插件包中复制账号、密码、连接串、令牌和额外的业务数据。
