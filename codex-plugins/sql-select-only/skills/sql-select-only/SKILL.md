# 数据源只读 SELECT

1. 使用本技能目录下的 `scripts/select_only.py`，通过 Python 3.10 或更新版本运行。Windows 上通常使用 `python`，其他系统通常使用 `python3`。默认连接清单为本机的 `E:/项目/connections.ncx`。使用另一份清单时，在子命令前加 `--connections "<文件>"`。

   ```text
   python -B "<脚本>" list
   python -B "<脚本>" match-mysql
   python -B "<脚本>" validate --source-id <连接编号>
   ```

2. 结合连接清单、项目文档和已有服务配置确认目标环境、数据库及方言。拟查库名为空或登记名称有歧义时，先核对实际配置入口。将仅含 `host`、`port`（整数，默认 3306）、`database` 和可选 `username` 的 JSON 对象通过本地标准输入交给 `match-mysql`。返回值列出端点匹配的直连条目及库名、登录名的匹配状态。状态为 `null` 表示字段缺项。通过配置或只读证据还无法确认目标时，再请用户确认。连接的 `supported` 为 `false` 时说明缺少支持的 SQL 方言。

3. 根据已确认的表结构和业务键拟写单条查询。先查项目数据字典、实际服务入口及查询实现，必要时用该方言的目录视图只读核对相关表和列。将环境、库名、标识符及外部输入视为数据。需要定位账套、跨库找数据、重算余额或解释报表差异时，读取 [数据库只读对账](references/database-reconciliation.md)，按实际项目的分库和取数规则执行。涉及改数据、建对象、授权、执行过程、加锁或服务端导出文件时，说明只读范围。

4. 将 SQL 文本通过标准输入交给 `validate`，使用安全字面量、标准输入或文件重定向传递。退出码为 0、`status` 为 `accepted` 且返回 `sql` 时，才展示或执行返回的原样 SQL。一次提交单条语句，多步对账时逐条校验并注明执行库。校验未通过时可改写为受支持的只读语法后重验，否则如实说明。校验通过只证明语句形式符合要求，数据库连接、权限和业务口径另行核对。

5. 用户要求定位故障、解释业务差异或给出解决方案时，读取[数据库只读对账](references/database-reconciliation.md)的方案交付规则。按每条问题分别给出事实与证据、至少三种实质不同的可选方案，以及一个当前首选和推荐理由。每种方案要写明适用条件、具体动作、影响与回退方式、验收标准。当前未复现或缺少历史证据时，给出可立即采用的处理和有明确启用条件的备选方案。用户只要查询或校验 SQL 时，按前四步交付。

插件提供查询思路、经校验的 SQL 文本、数据源匹配结果和故障诊断方案。用户明确授权实际查询后，才使用独立的已确认数据源和只读会话，逐次执行批准的 SELECT。Python 直连时将凭据保留在原始配置和进程内，并确保驱动只发出获准的 SQL。对外输出去掉登录信息和连接凭据。
